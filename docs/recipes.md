# Aquarium Monitor Card: Recipes

Home Assistant `template` sensors that plug into this card. The card reads
entities; these build the entities it cannot build itself. Paste a block into
your Home Assistant configuration, reload templates, and point the card at the
entity it creates.

Every entity id written `sensor.YOUR_SOMETHING` is a placeholder for one of
yours. Nothing on this page is a card option, and nothing here needs a new
release of the card to work.

## Reading the card's own bands from an automation

The card colours a reading and names its band on screen, and that name never
leaves the browser. These sensors put the same name in an entity state, so an
automation can trigger on it:

```yaml
trigger:
  - platform: state
    entity_id: sensor.ammonia_band
    to: "Very Poor"
```

The four boundaries and their order are the card's own, read from the same
registry the card reads, so a threshold that moves in a release moves here
too. What the card does *not* apply, and neither do these, is any per-sensor
`limits` you wrote in your own card configuration: these follow the presets.

**Not verified.** These blocks have not been run on a Home Assistant instance. Their numbers and their band order are checked against the card by a test; their YAML is not.

### Ammonia (`ammonia`)

| Reading, in ppm | Band |
| --- | --- |
| below 0.25 | Good |
| 0.25 to 0.5 | Fair |
| 0.5 to 1 | Moderate |
| 1 to 2 | Poor |
| 2 and above | Very Poor |

```yaml
template:
  - sensor:
      - name: "Ammonia band"
        unique_id: ammonia_band
        state: >
          {% set v = states('sensor.YOUR_AMMONIA') | float(0) %}
          {{ 'Good' if v < 0.25 else 'Fair' if v < 0.5 else 'Moderate' if v < 1 else 'Poor' if v < 2 else 'Very Poor' }}
        availability: "{{ states('sensor.YOUR_AMMONIA') | is_number }}"
```

Sources the registry cites for these bounds: <https://ask.ifas.ufl.edu/publication/FA031>, <https://www.globalseafood.org/advocate/nitrite-toxicity-affected-by-species-susceptibility-environmental-conditions/>.

### Salinity (`salinity`)

| Reading, in ppt | Band |
| --- | --- |
| below 1 | Good |
| 1 to 3 | Fair |
| 3 to 10 | Moderate |
| 10 to 35 | Poor |
| 35 and above | Very Poor |

```yaml
template:
  - sensor:
      - name: "Salinity band"
        unique_id: salinity_band
        state: >
          {% set v = states('sensor.YOUR_SALINITY') | float(0) %}
          {{ 'Good' if v < 1 else 'Fair' if v < 3 else 'Moderate' if v < 10 else 'Poor' if v < 35 else 'Very Poor' }}
        availability: "{{ states('sensor.YOUR_SALINITY') | is_number }}"
```

Sources the registry cites for these bounds: <https://www.usgs.gov/special-topics/water-science-school/science/saline-water-and-salinity>.

**This recipe follows `tank_type: freshwater`.** `tank_type: reef` drops the bands entirely and centres the scale on 35, so on that tank the sensor above would disagree with the card.
